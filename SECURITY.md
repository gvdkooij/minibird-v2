# Security review for Issue #1

Reviewed authentication and authorization: Argon2id password verification; signed, HttpOnly, SameSite=Strict session cookies; Secure by default; eight-hour expiry. All customer, settings, document and PDF routes require authentication. First-run initialization is transactional and must happen over a trusted local connection before public deployment. Five failed logins per peer within fifteen minutes are persisted in SQLite. Behind the reverse proxy the limit is shared; spoofed forwarded headers are ignored by the documented production command.

Reviewed CSRF: every mutation requires both a session-issued random token and a matching submitted token, including setup/login/logout. Tests include absent, forged and Unicode tokens. Tokens are rotated at authentication boundaries. Logout clears the browser cookie; signed cookies are stateless and a stolen cookie remains usable until expiration or secret rotation. There is no remote session revocation UI.

Reviewed injection and escaping: bound SQLite parameters; Jinja autoescaping; no user HTML marked safe; CSP blocks inline JavaScript; fixed numeric document routes and generated PDF names. Money uses finite bounded Decimal values with integer cents and explicit half-up rounding. Email addresses exclude header injection. SMTP always verifies TLS certificates through STARTTLS; secrets are encrypted at rest and never returned to forms or logs. SMTP host settings are available only to the trusted administrator; this app does not attempt to sandbox administrator-configured destinations.

Reviewed document integrity: transaction-protected unique counters, immutable customer/company snapshots, explicit status transitions, idempotent quote conversion and no deletion of issued documents. Deleted draft numbers are not reused. Issued corrections require an external linked credit note as documented. No bank integration or automatic payment reconciliation is implied.

Reviewed persistence and operations: versioned SQLite initialization, integrity-checked online backup, restore/restart test, default 0600 database permissions. Use a private data directory and unprivileged service with umask 0077. Preserve the encryption/session key outside source control. No public preview, external email, or production financial data was used during validation. HTTPS proxy and local initial setup are mandatory before public use; deployment remains an operator action.

Validation: 25 unit/integration cases and a Chromium workflow, clean installation, pip dependency checks and dependency vulnerability scan. The final dependency scan returned no known vulnerabilities at execution time; this is not a guarantee against undiscovered vulnerabilities. Tests use only temporary fictional data and mocked SMTP. This is an implementation review, not an independent penetration test.
